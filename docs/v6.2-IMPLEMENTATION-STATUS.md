### 3.3 未实现项原因

#### 原因 1:R11(pipeline.ValidateBuildEnvironment)/ R4(用户只能选预置)未做

**直接原因**:这两个阶段都在阶段 12(build 包接入 env_resolver)的下游——build 包没动,pipeline 校验自然没动。
**深层原因**:阶段 12 触及 dag_stage_exec / script_steps / builder 三个核心文件,改动面大,需真实 docker 环境跑通才能验;沙箱无 docker,**无法在沙箱联调**。
**现有防护**:R4 在前端 UX 层面已做(前端让用户从 build_env 列表选,不直接输入镜像),所以**误用风险有限**,但后端没卡住。
**后续**:独立 story,需有 docker 的开发机 + 一组真实流水线 fixture 才能落地。

#### 原因 2:R12(build 包接入 env_resolver)未做

**直接原因**:同上,沙箱无 docker,改 build 包风险高、无法在沙箱联调。
**现状影响**:job 仍走原 `toolchainImage()` 路径(阶段 12 没接 → `buildenv.ResolveImage` 不被调用),v6.2 阶段 12 这个 milestone 推迟。
**后续**:同 R11,需 docker 环境。

#### 原因 3:阶段 20(ScriptJobEditor/ScriptStepEditor 适配环境选择器)未做

**直接原因**:`BuildEnvs` 列表前端已有(`/settings/build-envs`),但 ScriptJob/Step 编辑器内嵌环境选择器改造需要改 ScriptJob.vue / ScriptStep.vue 模板,**改动量大且需 UI 设计**。
**现状影响**:`e91957e` 之后只做了"build_env 在流水线列表的进度展示",ScriptJob/Step 编辑器内嵌选择未做——用户需在画布上配 job 时没法直接选 build_env,仍用 toolchain。
**后续**:与 R11/R12 同步做(都依赖 build 包接入 env_resolver)。

#### 原因 4(P0 #2):credentials 表 owner_id/enabled + scope/owner CHECK 未落地

**直接原因**:v6.2 阶段 1 早期尝试过 `0053_credentials_owner.sql`,改了 credentials 表加 owner_id/enabled/description 等列 + scope/owner CHECK 约束,**导致 25+ 单测的 `INSERT INTO credentials` 头部被破坏**(legacy 单测 helper 写死 8 列 INSERT,新 CHECK 约束报错),为不阻塞主线而撤销迁移。
**当前妥协**:`vault.Credential` Go struct 已加 `OwnerID/Description/Enabled/DisabledBy` 字段(语义预留),`vault.ListWithActor/DisableWithActor` 走兼容 SQL(只按 scope 过滤,owner_id 等字段填空)。
**直接后果**:
- `GET /api/credentials` 返回**全量**(不按 owner 过滤)
- `POST /api/admin/credentials/{id}/disable` 返回 200 但 DB 不变(无 enabled 列)

**待你决策(见 `docs/MANUAL-VERIFICATION.md` §4)**:
- **A**:保留现状(等 0053 重做时一并生效)
- **B**:现在就把 disable 端点改为 501 + 前端 banner 提示「功能暂未启用」,避免误导

#### 原因 5:邀请注册流(C2)未做

**直接原因**:计划里"完整用户管理"是阶段 17 后的独立 story(计划 §九 注释提到 "完整用户管理(邀请注册/启用禁用)是后续 story")。
**现状**:`/api/admin/users` 列表已通(阶段 9),但**没有邀请端点**(`POST /api/admin/users/invitations`、`POST /api/auth/register`)。
**联调 workaround**:用 `cmd/tmp-mkuser/main.go` 临时程序 + `auth.HashPassword` 直接 INSERT 一条普通用户(alice)进 users 表。
**后续**:独立 story。

#### 原因 6:ConfigInjector 拷贝进容器(C4)未做

**直接原因**:同原因 2(build 包未动)。
**现状影响**:`config_profile` 当前只落磁盘 + DB,runner 不会拷贝进容器;构建时流水线看不到这些配置。
**后续**:同 R11/R12。
